# n8n-sdd

Шаблон репозитория для разработки воркфлоу n8n от спецификации (spec-driven development, SDD).

Сначала пишется спека: что воркфлоу делает, на что реагирует, что возвращает, как ведёт себя при ошибках.
Потом Claude Code собирает воркфлоу в n8n по этой спеке, прогоняет тест-кейсы и выгружает результат обратно в репозиторий.
Источник правды — репозиторий, n8n — среда исполнения.

Спеки ведутся в [OpenSpec](https://github.com/Fission-AI/OpenSpec) по собственной схеме `n8n-workflow`.
Воркфлоу собираются через MCP-сервер [n8n-mcp](https://github.com/czlonkowski/n8n-mcp): через него Claude Code работает с n8n напрямую.

## Что нужно

- Node.js 20 или новее
- [Claude Code](https://claude.com/claude-code)
- Инстанс n8n с включённым публичным API и ключ к нему

## Настройка

1. Склонировать репозиторий и поставить зависимости:

   ```
   git clone git@github.com:yatolstoy/n8n-sdd.git
   cd n8n-sdd
   npm install
   ```

2. Создать файл с доступами к n8n:

   ```
   cp .env.example .env
   ```

   Заполнить в `.env`:
   - `N8N_API_URL` — адрес инстанса, например `https://n8n.example.com`, без `/api/v1`
   - `N8N_API_KEY` — ключ из n8n: Settings → n8n API → Create an API key
   - `N8N_MCP_ACCESS_TOKEN` — необязательно. Токен встроенного MCP n8n (Settings → Instance-level MCP). Даёт доступ к справочникам credentials и к истории версий

   Файл `.env` в git не попадает. Ключи в любых других файлах репозитория запрещены.

3. Открыть папку в Claude Code. Он спросит разрешение на MCP-сервер `n8n-mcp` из `.mcp.json` — согласиться.
   Если `.env` поменялся, Claude Code нужно перезапустить: MCP-сервер читает ключи только при старте.

4. Проверить связь — попросить Claude Code: «проверь подключение к n8n». Он вызовет проверку здоровья инстанса и покажет список воркфлоу.

## Как работать

Одно изменение проходит пять шагов. Команды со слешем вводятся в Claude Code.

| Шаг | Что делать | Что получится |
|---|---|---|
| 1. Предложение | `/opsx:propose "что нужно сделать"` | Папка `openspec/changes/<изменение>/` с четырьмя документами: предложение, спека, дизайн, план задач. В n8n ничего не меняется |
| 2. Ревью | Прочитать документы, поправить спеку и дизайн | Согласованный план. Дальше спека не меняется без повода |
| 3. Сборка | `/opsx:apply` | Claude Code собирает воркфлоу в n8n выключенным, прогоняет тест-кейсы, выгружает JSON в `workflows/`, проверяет правила проекта |
| 4. Коммит | Спека и JSON воркфлоу — в одном коммите | История изменений поведения и реализации идёт вместе |
| 5. Архив | `/opsx:archive` | Изменения спеки вливаются в `openspec/specs/<воркфлоу>/spec.md` — актуальное описание воркфлоу |

После этого воркфлоу включается в n8n. Claude Code делает это только с согласия человека.

Когда задача ещё не ясна, сначала можно подумать вместе: `/opsx:explore "тема"`. Этот режим ничего не создаёт.

### Четыре документа изменения

- **proposal.md** — зачем и что меняется, какие внешние системы затронуты. Не больше страницы.
- **specs/<воркфлоу>/spec.md** — поведение воркфлоу. Шесть обязательных требований:
  - Trigger — что запускает воркфлоу;
  - Input contract — какие данные он принимает;
  - Output and side effects — что возвращает и что меняет во внешних системах;
  - Error handling — что происходит при ошибке;
  - Idempotency — что будет при повторном запуске с теми же данными;
  - Credentials — какие подключения к сервисам нужны.
  
  Дальше идут бизнес-требования. Каждое требование сопровождается сценариями «дано — когда — тогда». Названий нод n8n в спеке нет.
- **design.md** — как это устроено в n8n: цепочка нод, подключения, Code-ноды, обработчик ошибок, окружение.
- **tasks.md** — чеклист сборки. Последняя группа «Проверка и фиксация» одинакова во всех изменениях.

Структурные заголовки документов на английском (так требует OpenSpec), текст — на русском.

## Правила проекта

Полный текст — в `openspec/config.yaml`. Коротко:

1. Имя воркфлоу в n8n = имя спеки = имя файла в `workflows/`, в kebab-case (строчные латинские буквы через дефис).
2. Секреты только в credentials n8n. В репозитории — только имена credentials.
3. Первая нода каждого воркфлоу — Sticky Note (заметка на холсте) с путём к спеке.
4. У каждого рабочего воркфлоу назначен обработчик ошибок (Error Workflow).
5. Code-нода не длиннее 50 строк. Больше — выносим из n8n.
6. На каждый сценарий спеки есть тест-кейс в `tests/<воркфлоу>/`.
7. Спека и JSON воркфлоу меняются только вместе, одним коммитом.
8. Повторный запуск с теми же данными не создаёт дублей. Если это невозможно, спека говорит об этом явно.
9. Стенд один и рабочий. Новый воркфлоу создаётся выключенным. Включение и правка уже работающего воркфлоу — только с согласия человека. Тесты не пишут в настоящие CRM, Notion и почту: только тестовые записи или pin data (сохранённые данные вместо настоящего вызова).

Правила 1, 2, 3, 4, 5 и 6 проверяет `npm run check`.

## Команды

```
npm run export -- <воркфлоу>   # n8n → workflows/<воркфлоу>.json, с очисткой служебных полей
npm run export -- --all        # выгрузить все воркфлоу инстанса
npm run import -- <воркфлоу>   # workflows/<воркфлоу>.json → n8n; обновляет по имени или создаёт новый, включение не трогает
npm run check -- <воркфлоу>    # проверка правил проекта; --all — по всем файлам в workflows/
npm run validate               # проверка всех спек OpenSpec
```

Выгрузка убирает то, что меняется при каждом сохранении в n8n: идентификатор, даты, версию, pin data. Признак включения всегда сбрасывается в «выключен».
Поэтому в `git diff` видны только настоящие изменения воркфлоу.

## Структура

```
openspec/
  config.yaml                  правила проекта и контекст для Claude Code
  schemas/n8n-workflow/        схема и шаблоны четырёх документов
  specs/<воркфлоу>/spec.md     актуальные спеки
  changes/<изменение>/         изменения в работе; changes/archive/ — завершённые
workflows/<воркфлоу>.json      выгрузки воркфлоу, руками не редактируются
tests/<воркфлоу>/              тест-кейсы: case-NN.input.json и case-NN.expected.json
scripts/                       выгрузка, загрузка, очистка, проверка правил, запуск MCP
.claude/                       команды /opsx:*, генерируются OpenSpec — не править руками
CLAUDE.md                      инструкция для Claude Code
```

Схему и шаблоны документов меняют в `openspec/schemas/n8n-workflow/` и `openspec/config.yaml`.
Файлы в `.claude/` перезаписываются командой `npx openspec update`.

## Существующие воркфлоу

Шаблон рассчитан на воркфлоу, которые создаются по спеке с нуля.
У уже работающих воркфлоу имена обычно не проходят правило 1: в них пробелы, «|», кириллица.
При первом изменении такого воркфлоу его нужно завести в репозиторий: написать спеку по текущему поведению и решить вопрос с именем.
